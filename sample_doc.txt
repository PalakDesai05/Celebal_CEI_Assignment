Retrieval-Augmented Generation (RAG) Overview

RAG is a technique that combines information retrieval with text generation.
Instead of relying only on what a language model learned during training,
RAG retrieves relevant chunks of text from an external knowledge source (like
your own documents) and feeds them to the model as context before generating
an answer. This makes RAG especially useful for private, custom, or
frequently-updated data that the base model was never trained on.

How a RAG pipeline works:
1. Load documents (PDF, TXT, DOCX, etc.)
2. Split the documents into smaller chunks (e.g. 500 characters) so they fit
   within the model's context window and retrieval is more precise.
3. Convert each chunk into a vector embedding using an embedding model such
   as all-MiniLM-L6-v2.
4. Store the embeddings in a vector database (e.g. FAISS, Chroma, Pinecone).
5. When a user asks a question, embed the question and search the vector
   database for the most similar chunks (top-k retrieval).
6. Pass the retrieved chunks along with the question to a language model,
   which generates a grounded, context-aware answer.

Benefits of RAG:
- Reduces hallucination by grounding answers in real source text.
- Works with private or domain-specific data without retraining the model.
- Cheaper and faster than fine-tuning a model on new data.
- Easy to update: just add new documents to the vector store.

Common tools used to build RAG systems: LangChain, LlamaIndex, FAISS, Chroma,
Hugging Face Transformers, and Sentence-Transformers.
